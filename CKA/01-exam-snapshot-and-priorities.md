# Executive Summary

You don't need to re-learn Kubernetes — the CKAD baseline (Deployments, Services, ConfigMaps/Secrets, probes, basic NetworkPolicy) is confirmed to overlap heavily with the lower-weighted CKA domains, and you already have that cold. What's actually being tested now is **administrator judgment under time pressure**: Troubleshooting is the single largest domain at 30% (bigger than any other domain, and the one every independently-fetched 2026 source converges on), and Cluster Architecture, Installation & Configuration is 25%. Cluster Architecture (25%) is almost entirely new ground for a CKAD holder; within Troubleshooting (30%), the control-plane/node/CNI/kubelet diagnosis is the genuinely new part, while two of its five official bullets — monitoring resource usage and evaluating container output streams/logs — are app-level skills you already exercise routinely from CKAD. Your highest-leverage prep is real kubeadm reps on actual multi-node VMs (not kind/minikube, which abstract away exactly what's tested), drilled until `kubeadm init/join/upgrade`, etcd snapshot backup/restore, cert inspection, and kubelet/CNI/DNS diagnosis are muscle memory rather than lookups. Generate YAML, don't hand-write it (`--dry-run=client -o yaml`, `kubectl get -o yaml`) — this is stated independently by multiple fetched 2026 sources and is exactly the workflow you already use from CKAD. Two nuances worth internalizing before you touch a keyboard: `etcdctl` backs up, `etcdutl` restores (not interchangeable), and Kustomize has no exam-allowed documentation domain, so `kubectl apply -k` fluency has to be memorized, not looked up. Finally, treat the Kubernetes version target (currently v1.35 per official pages, with v1.36 already GA) as a moving target — re-verify on the live LF page within a week or two of booking.

# What Changed Recently

## Old CKA Advice That Is Now Outdated

- **"Exam is on v1.31/v1.32" framing.** Several community repos (e.g., `chadmcrowell/CKA-Exercises`, last pushed 2025-10-08 — about 10 months before this writing) contain README prose stating "the CKA exam is currently on v1.31" — this is stale. The confirmed current curriculum file is `CKA_Curriculum_v1.35.pdf`. **Lesson: recent commit activity in a repo does not guarantee current version-specific prose inside it** — check the text itself, not just the push date.
- **Docker/dockerd as the exam's container runtime.** Community claims exist about this, but they are unverified and technically doubtful — dockershim was removed from Kubernetes in **v1.24 (2022)**, and a v1.35-aligned environment would default to containerd. If a real task touches a container runtime, it's more plausibly a deliberately broken/misconfigured-runtime troubleshooting scenario than a blanket "exam uses Docker" fact.
- **PodSecurityPolicy (PSP) as current practice.** Confirmed removed in **Kubernetes v1.25**, replaced by Pod Security Admission (stable as of that release). Any material still teaching PSP as the live mechanism is outdated.
- **Play with Kubernetes (`labs.play-with-k8s.com`) as a free scratch environment.** Confirmed dead — the live site itself carries a banner stating it became unavailable starting **2026-03-01**. Drop this from any bookmark list or older study guide.
- **"Gateway API / Helm docs are restricted during the exam."** Contradicted by the current official allowed-resources page — both `helm.sh/docs/` and `gateway-api.sigs.k8s.io/` (CKA only) are explicitly permitted. If candidates found these hard to use, it's more likely the "no external search results, in-site search only" rule biting people unfamiliar with navigating those sites directly, not an actual block.
- **"Killer.sh is now easier than the real exam" / consensus shift.** The one independently-fetched and read source most recent to this writing (Jan 2026, passitexams.com) states killer.sh is "intentionally more difficult" than the real exam — the traditional consensus, not a reversed one. Treat any claim of a "shifted consensus" with skepticism.
- **`ETCDCTL_API=3` as something you must actively remember to set.** Still shown in example commands for compatibility, but etcd v3.4+ already defaults to API v3 — this is now largely a legacy carry-over from older tutorials, not a live gotcha.

## Newer CKA Areas I Must Not Miss

- **Troubleshooting is now the largest single domain (30%)**, ahead of Cluster Architecture (25%). This is the strongest, most cross-source-confirmed change in the whole research set — official weighting plus every independently-fetched 2026 community article agrees the exam's center of gravity has moved to control-plane/kubelet/node/CNI/DNS diagnosis via logs and events, away from "build something from scratch."
- **Curriculum overhaul (window: roughly Feb 2025, exact date unverified)** added, as officially confirmed curriculum content: **Helm and Kustomize** (for cluster component installation), **CRDs and operators**, and **Gateway API** (for ingress traffic management). These are new enough that older prep material predating the overhaul may not cover them at all.
- **`etcdctl` vs `etcdutl` is a genuine tool-boundary split, not just a naming quirk.** Use `etcdctl snapshot save` for backup (network-capable, talks to a running cluster) and `etcdutl snapshot restore` for restore (offline, operates directly on data files). `etcdctl`'s own restore subcommand has been deprecated/removed in favor of `etcdutl` since etcd v3.5 — get this exactly right, it's a near-guaranteed task tied to two of the highest-weighted domains.
- **Kustomize has no exam-allowed documentation domain.** Unlike Helm and Gateway API, there is no `kustomize.io` equivalent on the allowed-resources list. Any Kustomize task must be solvable purely from `kubectl kustomize`/`kubectl apply -k` fluency and kubernetes.io's own docs — plan to memorize this workflow rather than look it up mid-exam.
- **The exam's Kubernetes version is a genuinely moving target right now**, with some evidence LF's own stated 4–8 week update cadence may be running behind (v1.36 GA since June 2026, FAQ still says v1.35 as of this writing). Re-verify close to your actual booking date rather than trusting this document indefinitely.
