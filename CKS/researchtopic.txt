# FINAL OBJECTIVE

The goal is NOT simply to make me knowledgeable about Kubernetes security.

The goal is to train me until I see something such as:

```yaml
securityContext:
  privileged: true
```

and immediately think:

> "This container is privileged. I know the risk, I know the exact YAML field to change, I know which additional security settings I should inspect, and I can remediate and verify it in under a few minutes."

When I see excessive RBAC:

> "I know exactly how to identify the effective permission, reduce it to least privilege, and validate it with kubectl auth can-i."

When I see a networking requirement:

> "I can translate it directly into a NetworkPolicy without experimenting for ten minutes."

When I see suspicious runtime activity:

> "I know which tool to inspect, what signal matters, and how to isolate the affected workload."

Train me to think:

**DETECT → UNDERSTAND → REMEDIATE → VERIFY.**

Optimize everything for:

**PASSING THE CURRENT CKS EXAM ON MY FIRST ATTEMPT.**

Accuracy > quantity.

Current Kubernetes security practices > obsolete CKS tutorials.

Hands-on execution > passive learning.

Security remediation speed > theoretical depth.

Official documentation > memorizing giant YAML files.

Understanding attack paths > memorizing isolated settings.

Verification > assuming the task is complete.

Exam points > perfection.

Start by performing deep research.

Do NOT immediately generate the entire course from your internal knowledge.

First:

1. verify the current CKS exam blueprint,
2. verify the current Kubernetes version and exam environment,
3. research recent candidate experiences,
4. identify current high-frequency task patterns,
5. identify obsolete CKS preparation material,
6. build the P0/P1/P2/P3 priority model,
7. and only then construct my complete CKS preparation system.
